## 2. Tier 0 — near-free coverage fixes

### A1 · Python MCP `recall` / `recall_pack` can't reach the retrieval features · **S**

`mcp_server/server.py:156-169` accepts `query, k, type, tag, min_importance,
source, since, until, mode, overfetch, include_superseded, include_expired,
explain` — and nothing else. Compare:

| knob | store | HTTP | Go MCP | **Py MCP** |
|---|---|---|---|---|
| `fusion` (RRF) | ✓ | ✓ | ✓ | ✗ |
| `diversity` (MMR) | ✓ | ✓ | ✓ | ✗ |
| `dedup_threshold` | ✓ | ✓ | ✓ | ✗ |
| `min_cosine` | ✓ | ✓ | ✓ | ✗ |
| `touch=False` | ✓ | ✓ | ✓ | ✗ |
| `weights.graph` | ✓ | ✓ | ✗ | ✗ |
| `expand{…, rerank}` | ✓ | ✓ | ✗ | ✗ |

MCP is the *primary* consumer of this library. Three cycles of retrieval work —
RRF, MMR, dedup, the relevance gate, graph-proximity fusion, gated expansion —
is invisible to every agent talking to the Python server, and half-visible to
agents talking to the Go one. Mirror the HTTP body helpers as flat MCP params in
both ports; no store change required.

### A2 · `get()` is private but is the most-used method in the codebase · **S**

`MemoryStore._get_by_id` is called from the CLI (`cli/commands/edit.py:27,131,161`,
`show.py:20,33`), the HTTP server (`http_server/server.py:267,358,405`), 20+
internal sites, and a dozen places in `ai-houkai-service`. Promote it to a
public `get(memory_id) -> Memory | None`, add `AsyncMemoryStore.get`, add an MCP
`get` tool (the service already ships one), keep `_get_by_id` as a deprecated
alias for one release.

## 3. Tier 1 — the structural one

### B · Pluggable embedder in Python (`embedding_function=` seam + `ai_houkai.embed`) · **M**

Go injects both halves of the storage stack —
`NewMemoryStore(backend vector.Backend, embedder embed.Embedder, cfg)`
(`go/internal/memory/store.go:104`) with Ollama / OpenAI / DigitalOcean
providers behind `embed.Embedder` (`go/internal/embed/embedder.go:5-9`).
Python hard-wires `SentenceTransformerEmbeddingFunction` at
`store.py:74-97` and `:643`, with no override parameter anywhere.

What that costs today:

- **Weight.** `pip install ai-houkai` drags torch — this repo's `.venv` is
  **5.4 GB**, 1.2 GB of it torch — for a library whose README sells "no LLM
  provider required for the memory layer itself". No slim container, no
  serverless, no ARM SBC.
- **No hosted embeddings from Python at all**, though the Go binary has had them
  for months. The service inherits the limitation.
- **Test speed: 337 s vs. < 1 s.** The Go suite finishes in under a second
  because `stubEmbedder{dim: 16}` is injectable
  (`go/internal/httpserver/server_test.go:22-27`). The Python suite loads a real
  MiniLM — 831 tests in **5 m 37 s**, and only with `HF_HUB_OFFLINE=1`.
  *That single fact is what makes CI unattractive.*
- Blocks ROADMAP's `ai_houkai.testing`, which already names this seam as its
  prerequisite.

Sketch: add `embedding_function: EmbeddingFunction | None = None` to
`MemoryStore.__init__`, passed straight through to `get_or_create_collection`;
`embedding_model` stays the default path so existing callers are untouched. Add
`ai_houkai/embed.py` — a stdlib-`urllib` OpenAI-compatible embedder covering
OpenAI, Ollama's `/v1`, vLLM, llama.cpp and DigitalOcean, mirroring
`go/internal/embed/openai.go`. Move `sentence-transformers` to an optional
`[local]` extra (kept in `[all]`/`[dev]`) with a clear error when neither a local
model nor a remote provider is configured. `doctor`'s existing embed-dim
guardrail already covers the "swapped model, wrong dimensions" failure.

Falls out for free: `ai_houkai.testing.FakeEmbedder` (hash → deterministic unit
vector) + pytest fixtures → a sub-second Python suite.

### C · CI + release automation · **S–M**

No `.github/` at all, against 831 Python tests, ~330 Go test funcs, two ports
under a hard parity requirement, and a hand-built `dist/`. Minimum viable:

1. Python matrix 3.10–3.12 on the fake-embedder suite (needs B).
2. `go test ./... -race` + `go vet` + `gofmt -l`.
3. **A parity assertion that diffs the two MCP tool lists and the two CLI command
   lists and fails on drift.** A1 is exactly the failure this catches, and it is
   the only mechanical defence against the port skew this project keeps
   re-discovering by hand.
4. Tag-triggered wheel + cross-compiled `go build` release.

## 4. Tier 2 — graduate what the service already proved

### D · Move `ai-houkai-service/backend/app/memory_ops.py` into the library · **M–L**

The service implements eight memory operations by reaching through the library's
*private* API — `store._get_by_id`, `store._get_all_memories`,
`store.collection.update`, `store._journal`, `Memory.to_metadata`. Every one is a
store-level primitive that belongs here:

| op | service ref | why it belongs in the library |
|---|---|---|
| `merge_into(target, other)` | `memory_ops.py:119-185` | Combines text, transfers outgoing links, **re-points incoming links**, forgets the source. Re-pointing incoming edges requires a reverse-link walk only the store can do efficiently. |
| `versions(id)` | `:186` | Past text versions from the journal, incl. rotated segments. |
| `timeline(id)` | `:206` | |
| `list_tags` / `rename_tag` / `merge_tags` / `delete_tag` | `:234-299` | **There is no tag maintenance anywhere in the library** — yet `tag` is a first-class recall filter and tags accumulate typos forever. |
| `shortest_path(a, b)` | `:301` | BFS over undirected links. Its own comment records that a 2000-row cap "silently returned wrong *no path* results on larger collections" — the exact class of bug that belongs behind a library API with a real index (§E). |

Also worth graduating: **soft-delete trash** (`trash_list` / `trash_restore` /
`trash_purge`, service `db.trash_*`). The library jumps straight from `supersede`
(soft, but semantically "replaced by X") to `forget` (irreversible); `restore`
only undoes a supersede. A recoverable delete is the missing middle, and decay
pruning currently hard-deletes.

And `backup.py` — the service already has manifests, per-collection `.ahkai`
archives and a real restore, which is precisely ROADMAP Tier 3's "Quiesced backup
+ restore" item. `houkai backup` today is an unlocked `shutil.copytree` with no
restore path at all.

Payoff: proven demand, deletes the service's private-API coupling, both ports
gain the features, and ROADMAP Tier 3 shrinks.

## 5. Tier 3 — scale

### E · A metadata sidecar index (SQLite) — one change, five payoffs · **L**

Every one of these loads the entire collection into Python and filters in a loop:

| site | code |
|---|---|
| `list_recent` | `store.py:1388` — `collection.get()` with **no limit**, sort in Python, then `[:limit]` |
| `_get_all_memories` | `:2251` |
| `export` | `:1891` |
| `purge_expired` | `:1008` |
| `neighbors(direction="in"\|"both")` | `:1807` — see below |
| `stats` / id-prefix resolution | `cli/output.py:46` — **every CLI command that takes an id prefix** does a full load |
| `DecayEngine.score_all` | `decay.py:98-101` — `list_recent(limit=100_000)` |
| `ReflectionEngine._fetch_episodic` | `reflection.py:173-176` — all episodic docs **with embeddings** |

`neighbors` is worse than its own docstring admits: it promises "a full store
scan per hop", but `_get_all_memories()` sits inside the per-frontier-node loop
(`store.py:1784` → `:1807`), so `neighbors(depth=2, direction="both")` on a node
with ten neighbours performs **eleven** full-collection loads.

A single SQLite file beside `.chroma`, written in the same code path as
`collection.add/update/delete`, delivers:

1. **Full-corpus BM25 via FTS5** — ROADMAP Tier 1 #2. `_bm25_score_pool`
   (`store.py:427`) only ever scores the vector over-fetch pool, so a strong
   exact-token match with a weak embedding is unreachable *at any corpus size*.
2. **Pagination / cursors** on `list_recent` and `GET /memories`.
3. **O(1) reverse-link lookup** — kills the `neighbors` and `shortest_path` scans.
4. **Cheap `stats`, tag counts, per-scope aggregates** — the feeder for §D's tag
   ops and ROADMAP Tier 1 #1's scoping.
5. **Expiry sweep by index** instead of a full scan.

Keep Chroma authoritative; the sidecar is a *derived* index rebuildable by
`houkai reindex`, so a missing or corrupt sidecar degrades to today's behaviour
rather than losing data. Go can mirror it with `modernc.org/sqlite` (cgo-free) or
fold the index into the existing `vector.Backend` abstraction.

> **Sequencing:** build E *before* ROADMAP Tier 1 #1 (multi-tenant scoping).
> Scoping without an index just multiplies the full scans.

## 6. Tier 4 — retrieval quality

### F1 · Reflection only ever sees `episodic` · **M**

`_fetch_episodic` hard-codes `where={"type": "episodic"}` (`reflection.py:173-176`).
So semantic memories — **including reflections themselves** — never consolidate,
and a long-lived store accumulates summaries without bound; `feedback` and
`procedural` never benefit at all. Add a `types=("episodic",)` parameter and a
`level` tag so reflections-of-reflections form a hierarchy (Letta/MemGPT-style
tiering), with a `max_level` guard against runaway re-summarisation, wired into
`[maintenance.reflect]`.

Related: `_cluster` is O(n²) over a pure-Python `_cosine`
(`reflection.py:48`, `:197-233`) — fine at 1k memories, painful at 20k. Cheap
mitigation: cluster within a vector-index candidate pool instead of the full
cross-product.

### F2 · Wire `ai_houkai.eval` into CLI + MCP + Go · **M**

`eval.py` is complete (recall@k, P@k, MRR, MAP, nDCG; `evaluate()` forwards
arbitrary recall kwargs so ranking configs A/B cleanly) and reachable from
**nothing** — no CLI command, no MCP tool, no HTTP route, no Go port. The service
imports it directly (`analytics.py:16`). Ship
`houkai eval goldset.jsonl [--mode --fusion --graph …]` plus a read-only
`eval_recall` MCP tool.

This is the prerequisite for everything else in this section: graph damping
(0.5) and iteration count (3), the `β=0.20` lexical weight, MMR λ defaults and
the `graph` weight itself are all currently set by intuition with no way to
measure a change.

### F3 · Pinned / working-set tier · **S**

The only lever for "always consider this" is `importance`, which simultaneously
drives ranking, decay survival and the `min_importance` filter — three jobs, one
number. A boolean `pinned` (metadata, default `false`) that (a) makes
`recall_pack`/`auto_context` prepend pinned memories inside the budget and
(b) exempts from decay pruning and quota eviction, gives agents an explicit
standing-instruction slot.

### F4 · Idempotent `remember` via content hash · **S**

Agents re-assert the same fact every session. Today the only defence is
`on_conflict="supersede"`, which costs a 12-neighbour vector query per write
(`store.py:2371-2378`) and still creates a new row plus a supersede edge. Add a
normalised-text `content_hash` in metadata and `remember(idempotent=True)` →
return the existing memory and bump its access count instead of writing. Matters
most in `remember_many`, where the conflict scan is per item.

## 7. Tier 5 — one novel bet

### G · Provenance trust tier · **M**

AI-Houkai writes straight into agent context via `recall_pack` / `auto_context`.
Anything that reaches `remember` — a scraped page, a tool result, another
agent's output — becomes durable, well-ranked context in a later session.
`source` is a free-text provenance string with no semantics and no filtering
default.

Add `trust: "trusted" | "reported" | "untrusted"` (default `"trusted"`, so old
stores are byte-identical), set it at ingest boundaries (`houkai ingest`, HTTP
writes carrying a non-admin token, the service's per-user writes), let
`recall`/`recall_pack` filter on it, and let the packer annotate untrusted lines
so the consuming model can see the provenance boundary.

This is the memory-layer analogue of the instruction-source boundary agents
already enforce at the tool layer, and no comparable system (Mem0, Zep/Graphiti,
Letta, LangMem, cognee) ships it. Best-effort labelling, not a security
guarantee — same framing as ROADMAP's PII item.

## 8. Suggested order

1. **A1 + A2 + A3** — a few days; immediately unblocks agents on features that
   are already built and paid for.
2. **B** (embedder seam) → **C** (CI, using the fake embedder B enables).
3. **F2** (eval wiring) — you need a ruler before tuning anything below.
4. **E** (sidecar index) — the enabler for full-corpus BM25, pagination, and
   Tier 1 scoping.
5. **D** (graduate `memory_ops` + trash + backup from the service).
6. **F1 / F3 / F4**, then **G**.

ROADMAP's remaining Tier 3/4 items (quota + eviction, PII scanner, at-rest
encryption, journal checksums + compaction, bi-temporal validity, entity channel,
conversation fact-distillation) stay valid as written. I'd re-rank **quota +
eviction** upward — it is the one ops feature with no workaround today, since
decay pruning is the only bound on store growth and it is time-based, not
size-based.
